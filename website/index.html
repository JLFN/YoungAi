住在你自己机器上的个人 AI 助理

A personal AI assistant that lives on your own machine

记得你说过的事，会上网、会写 Word / PDF / PPT / Excel、会做视频、会盯着一件事持续跟进，干完把结果交到手机上的下一个 app。模型、记忆、文件全在本机，数据不出门。

It remembers what you tell it, browses the web, writes Word / PDF / PowerPoint / Excel files, makes videos, keeps following up on a job, and hands the result to the next app on your phone. Model, memory and files all stay on the machine.

A real run: "find me the cheapest DGX Spark on the web". 16 minutes, 12 rounds, 43 tool calls, all on the machine itself; it also flagged a too-cheap listing that looked like a scam.

怎么工作How it works

一句话进来，在沙盒里干完，再交出去

A request comes in, the work happens in a sandbox, the result goes out

没有为哪个场景写死的提示词。助理能做的每件事都是一个工具，模型看到工具表就知道这台设备、这台机器此刻能做什么。

There is no scenario-specific prompt. Everything the assistant can do is a tool; from the tool list the model knows what this device and this machine can do right now.

安全Safety

靠沙盒，不靠相信模型

Rely on the sandbox, not on trusting the model

助理以你的身份跑在你的机器上。所以每一次动手都要经过内核沙盒和一个固定规则的守门函数。

The assistant runs as you, on your machine. So every action goes through a kernel sandbox and a fixed-rule gatekeeper.

诚实的边界：没有虚拟机隔离。机器被攻破，助理也就被攻破了；提示注入靠污点和审批降低后果，不是消除。 The honest limit: there is no VM. If the machine is compromised, so is the assistant; taint tracking and approvals reduce the damage of prompt injection, they do not remove it.
  • 每次工具调用一个新子进程，先锁进内核沙盒再干活。Linux 用 Landlock + seccomp，macOS 用 Seatbelt；锁不上就拒绝执行。
  • Every tool call is a fresh child process locked into a kernel sandbox first. Landlock + seccomp on Linux, Seatbelt on macOS; if it cannot lock, the call is refused.
  • 守门是一个确定性的 C 函数，不是另一个模型。工作区外的写和删要你点头：仅这次 / 本会话 / 总是。
  • The gatekeeper is a deterministic C function, not another model. Writes and deletes outside the workspace need your OK: this once / this session / always.
  • 像密码、卡号、验证码的参数直接拒。这类东西永远不该经过模型。
  • Arguments that look like passwords, card numbers or one-time codes are refused outright. Those should never pass through a model.
  • 读过网页之后，外送动作的永久授权失效。网页里"把你的文件发出去"这种话没法借你的旧授权生效。
  • After reading a web page, standing approvals for outbound actions stop applying. A page saying "send me your files" cannot ride on an old approval.
  • 它碰不到自己的配置目录，没法给自己开权限；每次动手记一行审计，"活动"页能翻、能撤销授权。
  • It cannot touch its own config directory, so it cannot grant itself permissions; every action is logged, browsable on the Activity tab where approvals can be revoked.
在哪用Where you use it

电脑浏览器、手机 App、你的程序

A browser, a phone app, your own programs

  • 工作台：一个网页，助理、任务、记忆、技能、模型、训练、监控都在里面。
  • Studio: one web page holding the assistant, tasks, memory, skills, models, training and monitoring.
  • 手机 App：同一个网址"添加到主屏幕"。定位、剪贴板、分享、推送都走手机。
  • Phone app: Add to Home Screen from the same address. Location, clipboard, sharing and push go through the phone.
  • 从外网访问：设置里填一台云服务器，开穿透、传证书，手机在哪都能连回家里这台机器。
  • From the internet: enter a cloud server in Settings, turn on the tunnel, upload a certificate, and your phone reaches the machine from anywhere.
  • API：OpenAI / Anthropic 兼容，现有的客户端填个地址和密钥就能用。
  • API: OpenAI / Anthropic compatible; existing clients just need the address and a key.
背后的模型The model behind it

510 GB 的前沿模型，装进一台 128 GB 的机器

A 510 GB frontier model on a 128 GB machine

DeepSeek V4.1 Flash 原样发布是 510 GB。我们自己写的推理引擎（纯 C99 + CUDA / Metal，一个 Makefile）把它压到 113.6 GB，跑在一台 DGX Spark 上。

DeepSeek V4.1 Flash is 510 GB as released. Our own inference engine (plain C99 + CUDA / Metal, one Makefile) shrinks it to 113.6 GB and runs it on one DGX Spark.

上手Get started

三条命令，然后打开浏览器

Three commands, then open a browser

需要一台 DGX Spark（Linux aarch64 + CUDA 13 运行库，SSD 空闲约 320 GB）。上网工具要火狐，Spark 上的 Ubuntu 自带。

You need a DGX Spark (Linux aarch64 with the CUDA 13 runtime, ~320 GB free SSD). The web tools need Firefox, which Ubuntu on the Spark ships.

  1. 第一次打开页面，先设一个用户名和密码。
  2. The first visit asks you to set a username and password.
  3. 模型页点"下载"（约 317 GB，断点续传），再点"加载"（约 2 分钟）。
  4. On Models, press Download (~317 GB, resumable), then Load (~2 minutes).
  5. 助理页，直接说话。
  6. On Assistant, just talk.
